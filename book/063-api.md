# The Public API

Each of gen.clj's namespaces carries a tier in its ns form: `{:api :stable}`,
`{:api :experimental}` or `{:api :internal}` (DESIGN.md §9). Through the 1.x
releases a stable namespace keeps its names, arities, result-map keys and
documented semantics; minor releases add to them. A removal waits for 2.0,
after a deprecation: `:deprecated` metadata and a note in the docstring,
nothing printed. An experimental namespace ships outside that promise, and an
internal one is not for code built on gen.clj, which this appendix leaves out.

The stable namespaces come first, by layer: each with the first paragraph of
its docstring, and every public function, macro and var with the first sentence
of its own. A protocol names its methods, which are listed as functions too.
Where a namespace's protocols are for other code to implement, a note says so:
through 1.x such a protocol keeps its methods and gains none. The experimental
namespaces follow, each by name and the first paragraph of its docstring. A
committed snapshot of the stable surface (`test/fixtures/api-snapshot.edn`)
fails a test when the surface changes, and `clojure -M:test -m gen.api write`
writes it after a deliberate change.

This page is written from the code (`clojure -M:test -m gen.book sync`), and
the book's test fails when it is out of date.

## Arrays and randomness

### gen.array

The array API every part of gen.clj is written against (docs/array-api.md).

- `(!= x y)`: Elementwise numeric inequality (bool).
- `(*)`, `(* x)`, `(* x y)`, `(* x y & more)`: Elementwise product,
  broadcasting.
- `*backend*` (dynamic): The backend for operations without array operands
  (creation functions).
- `(+)`, `(+ x)`, `(+ x y)`, `(+ x y & more)`: Elementwise sum, broadcasting.
- `(- x)`, `(- x y)`, `(- x y & more)`: Elementwise difference, broadcasting;
  negation with one argument.
- `(->clj x)`: The host value of x: a number or boolean for 0-d, nested vectors
  otherwise.
- `(/ x)`, `(/ x y)`, `(/ x y & more)`: Elementwise true division (always
  floating), broadcasting; the reciprocal with one argument.
- `(< x y)`: Elementwise x < y (bool).
- `(<= x y)`: Elementwise x <= y (bool).
- `(== x y)`: Elementwise numeric equality (bool); NaN is never equal.
- `(> x y)`: Elementwise x > y (bool).
- `(>= x y)`: Elementwise x >= y (bool).
- `(abs x)`: Elementwise absolute value.
- `(acos x)`: Elementwise inverse cosine, in \[0, π] (NaN outside \[-1, 1]).
- `(all x)`, `(all x opts)`: Logical and over :axis (all by default).
- `(all-particles x)`: Every particle of a batched value (gen.array.batch) on a
  leading axis, for a check or a bound over all of them; any other value as it
  is.
- `(all-true? x)`: Is every element of the bool array x true, across every
  particle of a batched value (gen.array.batch)?
- `(allclose? x y)`, `(allclose? x y {:keys [rtol atol equal-nan?]})`: Are x
  and y elementwise within atol + rtol·|y| (broadcasting)?
- `(any x)`, `(any x opts)`: Logical or over :axis (all by default).
- `(any-true? x)`: Is some element of the bool array x true, across every
  particle?
- `(arange stop)`, `(arange start stop)`, `(arange start stop step)`, `(arange
  start stop step {:keys [dtype]})`: A 1-d array \[start, stop) by step.
- `(argmax x)`, `(argmax x opts)`: Index of the maximum along :axis (of the
  flattened array by default); the first NaN wins.
- `(argmin x)`, `(argmin x opts)`: Index of the minimum along :axis (of the
  flattened array by default); the first NaN wins.
- `(array data)`, `(array data {:keys [dtype]})`: An array from host data: a
  number, a boolean, nested vectors of them, or a double\[].
- `(array? x)`: Is x an array value: a host scalar or a backend array?
- `(asin x)`: Elementwise inverse sine, in \[-π/2, π/2] (NaN outside \[-1, 1]).
- `(astype x dtype)`: x converted to dtype.
- `(atan x)`: Elementwise inverse tangent, in \[-π/2, π/2].
- `(atan2 x y)`: Elementwise angle of the point (x, y) from the positive x
  axis, in \[-π, π], broadcasting: (atan2 y x), as Math/atan2 and Julia's
  atan(y, x).
- `(backend x)`: The backend of x (\*backend\* for host scalars).
- `(backend-array? x)`: Is x a backend array (an array value that is not a host
  scalar)?
- `(backend-name b)`: The keyword naming backend b, as backend-named takes it:
  :jvm or :mlx.
- `(backend-named k)`: The backend called k: :jvm (pure Clojure, always
  available) or :mlx (M2, loaded on demand).
- `(batch-shape x)`: The batch axes of a batched value (\[n] for a batch of n
  particles; a batch may have several axes), or nil for a value that is not
  batched.
- `(batched-branch message data)`, `(batched-branch message data cause)`: The
  batched-branch error, ex-info with ::batched-branch true: one answer cannot
  serve every particle of a batch (gen.array.batch).
- `(batched? x)`: Does x hold one value per particle of a batched run
  (gen.array.batch, the batch tracer)?
- `(broadcast-shapes & shapes)`: The shape arrays of the given shapes broadcast
  to, as NumPy's broadcast_shapes and as the elementwise ops broadcast: the
  shapes aligned at their last axes, a missing leading axis counting as 1, each
  axis is the one size other than 1 there (1 where every size is 1).
- `(broadcast-to x new-shape)`: x broadcast to shape.
- `(ceil x)`: Elementwise ceiling.
- `(clip x lo hi)`: Elementwise clamp of x to \[lo, hi]; either bound may be
  nil.
- `(common-backend xs)`: The backend an op on all of xs runs on (\*backend\*
  when all are host scalars); throws when they come from unrelated backends.
- `(compile f)`, `(compile f opts)`: f compiled where the backend can: a
  function of the same arguments (arrays, or trees of them) returning what f
  returns (an array or a tree of arrays).
- `(concatenate xs)`, `(concatenate xs axis)`: Join arrays along an existing
  axis (default 0).
- `(concrete? x)`: Can x's values be read without forcing a lazy computation?
- `(cos x)`: Elementwise cosine.
- `(cosh x)`: Elementwise hyperbolic cosine.
- `(cumprod x)`, `(cumprod x opts)`: Inclusive cumulative product along :axis
  (default -1).
- `(cumsum x)`, `(cumsum x opts)`: Inclusive cumulative sum along :axis
  (default -1).
- `(custom-vjp f vjp)`: f with its gradient given by vjp: for code
  differentiation cannot see through (host arithmetic, a solver's iterations)
  or should not (a cheaper or steadier rule).
- `(defaults b)`: Backend b's default dtypes, {:float … :int …}
  (docs/array-api.md §5).
- `(diag x)`: The diagonal matrix of a vector, or the main diagonal of a
  matrix.
- `(digamma x)`: Elementwise digamma ψ(x) = d/dx log Γ(x): ten recurrence steps
  ψ(x) = ψ(x+1) - 1/x, then the asymptotic series (to x\^-12), with the
  reflection formula for x < 0.
- `(dtype x)`: The dtype keyword of x.
- `(dtype-kind dt)`: The kind of the dtype dt, a level of the promotion lattice
  (docs/array-api.md §5): :bool, :int (:int32, :int64, :uint32) or :float
  (:float16, :bfloat16, :float32, :float64).
- `(effective-backend b)`: b, or \*backend\* when \*backend\* wraps b: under a
  batch tracer (gen.array.batch), draws and other new values must be made on
  the wrapping backend even when every operand is unbatched.
- `(equal? x y)`: Do x and y have the same shape and numerically equal
  elements?
- `(erf x)`: Elementwise error function.
- `(erfinv x)`: Elementwise inverse error function (±Inf at ±1, NaN outside
  \[-1, 1]).
- `(eval! t)`: Force evaluation of every backend array in the tree t (a hint on
  eager backends: a no-op).
- `(exp x)`: Elementwise e\^x.
- `(expand-dims x axes)`: x with new size-1 axes at the given position(s) of
  the result.
- `(expm1 x)`: Elementwise e\^x - 1, accurate near 0.
- `(eye n)`, `(eye n {dt :dtype})`: The n×n identity matrix.
- `(flatten x)`: x as a 1-d array.
- `(floor x)`: Elementwise floor.
- `(floor-div x y)`: Elementwise floor division.
- `(full shape value)`, `(full shape value {dt :dtype})`: An array of the given
  shape filled with value: a host scalar or a 0-d array.
- `(full-like x value)`, `(full-like x value {dt :dtype})`: An array with x's
  shape, backend and (unless given) dtype, filled with value, a scalar (on
  value's backend when that wraps x's, as full).
- `(grad f)`, `(grad f opts)`: A function of the same arguments as f returning
  its gradient (see value-and-grad).
- `(host? x)`: Is x a host scalar: a Clojure number or boolean (a 0-d array)?
- `(isfinite x)`: Elementwise test for a finite value (bool).
- `(isinf x)`: Elementwise infinity test.
- `(isnan x)`: Elementwise NaN test.
- `(item x)`: The host number or boolean of a single-element array.
- `(lgamma x)`: Elementwise log |Γ(x)| (+Inf at the poles 0, -1, -2, … and at
  +Inf, -Inf at -Inf, as SciPy): Lanczos for x >= 0.5, the reflection formula
  below.
- `(linspace start stop n)`: n evenly spaced floats from start to stop
  inclusive.
- `(log x)`: Elementwise natural logarithm.
- `(log-beta a b)`: Elementwise log B(a, b) = log Γ(a) + log Γ(b) - log Γ(a +
  b).
- `(log-softmax x)`, `(log-softmax x {:keys [axis]})`: log of softmax along
  :axis (default -1), stable.
- `(log1p x)`: Elementwise log(1 + x), accurate near 0.
- `(logaddexp x y)`: Elementwise log(e\^x + e\^y), stable and exact at
  infinities: the backend's own op where it has one (MLX's, whose gradient is
  exact at ties under its autodiff), this composite otherwise.
- `(logcumsumexp x)`, `(logcumsumexp x opts)`: Inclusive log Σ exp along :axis
  (default -1), stable.
- `(logging-branches f)`: \[(f) e]: f's result, and the last batched-branch
  error raised during the call, caught or not (nil if none).
- `(logical-and x y)`: Elementwise logical and (bool).
- `(logical-not x)`: Elementwise logical not (bool).
- `(logical-or x y)`: Elementwise logical or (bool).
- `(logsumexp x)`, `(logsumexp x opts)`: log Σ exp(x) over :axis (all by
  default), stable, -inf for all -inf.
- `(matmul x y)`: Matrix product with NumPy semantics: 1-d operands are
  vectors, leading axes are batch axes and broadcast.
- `(max x)`, `(max x opts)`: Maximum over :axis (all by default; NaN
  propagates).
- `(maximum x y)`: Elementwise maximum (NaN propagates).
- `(mean x)`, `(mean x opts)`: Mean over :axis (all by default).
- `(min x)`, `(min x opts)`: Minimum over :axis (all by default; NaN
  propagates).
- `(minimum x y)`: Elementwise minimum (NaN propagates).
- `(mod x y)`: Elementwise remainder with the sign of the divisor, like
  clojure.core/mod.
- `(ndim x)`: The number of axes of x (0 for a scalar).
- `(negate x)`: Elementwise negation.
- `(ones shape)`, `(ones shape {:keys [dtype]})`: An array of ones.
- `(ones-like x)`: Ones of x's shape, backend and dtype.
- `(outer x y)`: Outer product of x and y (flattened).
- `(particle x i)`: Particle i's value of x, a value of a batched run
  (batched?): an unbatched array of the backend the batch wraps
  (particle-backend), of x's per-particle shape, the value particle i's own run
  would hold.
- `(particle-backend x)`: The backend a batched value's particles are arrays
  of: the one the batch tracer wraps, where each particle's own run computes.
- `(particles x idx)`: The values of x's particles at idx (host integers in
  \[0, n), in their order, repeats allowed), stacked: an unbatched array of
  shape (count idx) followed by x's per-particle shape, of the backend the
  batch wraps, particle's value of each from one gather.
- `(pick x idx)`: Index the last axis of x by the int array idx, broadcasting
  the remaining (batch) axes of x against idx.
- `(pow x y)`: Elementwise power.
- `(prod x)`, `(prod x opts)`: Product over :axis (all by default).
- `(reshape x new-shape)`: x with a new shape of the same size; one dimension
  may be -1.
- `(round x)`: Elementwise rounding to nearest, ties to even.
- `(scatter-add x indices updates axis)`: x with updates added at indices along
  axis, accumulating repeated indices: the transpose of take-along-axis.
  indices (an int array) and updates have one shape, equal to x's on every axis
  but axis.
- `(shape x)`: The shape of x as a vector of longs (\[] for 0-d).
- `(sigmoid x)`: Elementwise logistic function, stable for large |x|.
- `(sign x)`: Elementwise sign: -1, 0 or 1 (NaN for NaN).
- `(sin x)`: Elementwise sine.
- `(sinh x)`: Elementwise hyperbolic sine.
- `(size x)`: The number of elements of x.
- `(slice x axis start stop)`, `(slice x axis start stop step)`: Elements from
  start (inclusive) to stop (exclusive) by step along axis. nil means the end;
  negative values count from the end; step may be negative (as in NumPy).
- `(softmax x)`, `(softmax x {:keys [axis]})`: exp(x) normalized along :axis
  (default -1).
- `(softplus x)`: Elementwise log(1 + e\^x), stable for large |x|: x +
  log1p(e\^-x) above 0, log1p(e\^x) elsewhere, each branch given a safe input
  (so that the other's cotangent is not NaN).
- `(sqrt x)`: Elementwise square root.
- `(square x)`: Elementwise x\^2.
- `(squeeze x)`, `(squeeze x axes)`: x without its size-1 axes (or without the
  given ones, which must be size 1).
- `(stack xs)`, `(stack xs axis)`: Join arrays along a new axis (default 0).
- `(std x)`, `(std x opts)`: Standard deviation over :axis.
- `(stop-gradient x)`: x, with differentiation blocked.
- `(sum x)`, `(sum x opts)`: Sum over :axis (one or several; all by default).
- `(take x indices)`, `(take x indices axis)`: Gather along axis (default 0):
  the axis is replaced by the shape of indices (an int array or integer), so a
  single integer index removes the axis.
- `(take-along-axis x indices axis)`: Gather along axis with an int array of
  the same rank as x, broadcast against x on every other axis.
- `(tan x)`: Elementwise tangent.
- `(tanh x)`: Elementwise hyperbolic tangent.
- `(tracked? x)`: Is x a value being differentiated: inside a function under
  value-and-grad (or grad), an argument it differentiates or a float computed
  from one, recorded on the tape (gen.array.tape)?
- `(transpose x)`, `(transpose x perm)`: x with its axes permuted (reversed by
  default).
- `(tree-leaves t)`: The leaves of a tree of nested maps, vectors and seqs,
  depth first.
- `(tree-map f t)`: The tree t with f applied to every leaf (maps, including
  records, keep their type).
- `(truthy? x)`: The Clojure truthiness of x, for branching, the same on every
  backend: a boolean (host or a one-element bool array) by its value; any
  number, and any numeric array, true, as in Clojure; a bool array of several
  elements is ambiguous (an error: use all, any or where); any other value by
  Clojure's rules.
- `(value-and-grad f)`, `(value-and-grad f {:keys [argnums]})`: A function of
  the same arguments as f returning \[value gradient]: f's value (a 0-d array)
  and its gradient with respect to the argument at :argnums (default 0), or a
  vector of gradients when :argnums is a vector.
- `(variance x)`, `(variance x opts)`: Variance over :axis (all by default).
- `(vmap f)`, `(vmap f opts)`: f batched over a leading axis, as JAX's vmap: a
  function of the same arguments that runs f once for the n particles of a
  batch, under the batch tracer (docs/array-api.md §8b).
- `(weak-dtype x)`, `(weak-dtype x b)`: The dtype x has on backend b (default
  \*backend\*): an array's own; a host scalar's is weak, its kind's default
  dtype there (so float64 only where that is the default).
- `(where c x y)`: Elementwise choice: x where condition c is true, y
  elsewhere, broadcasting.
- `(with-backend b & body)` (macro): Evaluate body with b as the backend for
  creation functions.
- `(xlog1py x y)`: Elementwise x·log1p(y), with 0·log1p(y) = 0 (also for y =
  -1).
- `(xlogy x y)`: Elementwise x·log(y), with 0·log(y) = 0 (also for y = 0).
- `(zeros shape)`, `(zeros shape {:keys [dtype]})`: An array of zeros.
- `(zeros-like x)`: Zeros of x's shape, backend and dtype.

### gen.array.linalg

Decompositions and solves over the last two axes of arrays, batched over the
leading axes. A right-hand side that is 1-d, or has one axis fewer than the
matrix, is a vector (batch); otherwise it is \[.. n k].

- `(cholesky a)`: The lower Cholesky factor L of a symmetric positive-definite
  a (a = L·Lᵀ).
- `(cholesky-logdet l)`: log det of a = L·Lᵀ from its Cholesky factor L: 2·Σ
  log diag(L).
- `(det m)`: The determinant.
- `(diagonal m)`: The main diagonals of \[.. n n] matrices, as \[.. n]: read,
  not computed (multiplied by the identity, an infinite entry made the zeros
  beside it NaN, genclj-d681).
- `(inv m)`: The inverse of a square matrix, in its float dtype.
- `(slogdet m)`: \[sign log|det m|] (sign 0 and -Inf for a singular matrix).
- `(solve m rhs)`: x with m·x = rhs (LU with partial pivoting).
- `(solve-triangular t rhs)`, `(solve-triangular t rhs {:keys [lower?
  transpose?]})`: x with t·x = rhs (or tᵀ·x = rhs) for triangular t.

### gen.array.protocols

The backend contract behind gen.array. Only backend implementers use this
namespace; model and inference code calls gen.array.

*For implementers:* the backend contract, which a new array backend implements.

- `(-all-particles x)`: The array of every particle's value, batch axes first.
- `(-arange b start stop step dtype)`: 1-d array \[start, stop) by step.
- `(-astype b x dtype)`: x converted to dtype.
- `(-backend x)`: The IBackend this array belongs to.
- `(-broadcast-to b x shape)`
- `(-compile b f opts)`: A function of a vector of leaf arrays (b's) returning
  a vector of leaf arrays: f, which takes and returns such vectors, traced once
  per input signature and replayed. opts: :shapeless?.
- `(-concatenate b xs axis)`: Join a vector of arrays along an existing axis.
- `(-custom-vjp b f vjp args)`: (apply f args), whose gradient comes from (vjp
  args out cotangent), a vector of one cotangent per argument (nil for none).
- `(-defaults b)`: Map of default dtypes: {:float :float64 :int :int64}.
- `(-dtype b x)`: Dtype keyword of x.
- `(-elementwise b op args dtype)`: Apply elementwise op to args (a vector of
  1-3 arrays), broadcasting with NumPy rules. dtype is the operands' common
  dtype (for :where, that of x and y; the condition is :bool); the result dtype
  is (gen.array.dtype/result-dtype op dtype).
- `(-eval! b xs)`: Force evaluation of the arrays in xs (a seq).
- `(-from-host b values shape dtype)`: An array of shape and dtype from host
  values in row-major order, as gen.array.host/parse gives them: a double\[] or
  a seq of numbers and booleans, as many as shape holds (one for shape \[], a
  0-d array).
- `(-full b shape value dtype)`: Array of the given shape filled with value.
- `(-inner b)`: The backend this one wraps.
- `(-lazy? b)`: Does this backend defer computation, so that reading a value
  forces evaluation?
- `(-linalg b op args)`: Decompositions and solves over the last two axes,
  batched over the rest.
- `(-matmul b x y)`: Matrix product with NumPy batching rules.
- `(-name b)`: Keyword naming the backend, e.g. :jvm or :mlx.
- `(-native-grad? b)`: Does -value-and-grad differentiate natively?
- `(-native-ops b)`: The optional ops this backend implements as primitive
  elementwise op keywords, a set. gen.array looks up one, :logaddexp: listed,
  it is an -elementwise op; otherwise gen.array composes it from primitives.
- `(-primal x)`: The value it tracks: an array of the backend the tape wraps,
  or a host scalar.
- `(-random-uniform b key shape dtype)`: Uniform \[0, 1) array of shape and
  dtype, a pure function of key (a gen.random key value, not an array).
- `(-reduce b op x axes keep-dims?)`: Reduce x over axes (a vector of distinct
  axes; empty reduces over no axis, the identity, as NumPy's axis=()). op is
  one of :sum :prod :max :min :argmax :argmin :all :any. :argmax and :argmin
  take a single axis.
- `(-reshape b x shape)`
- `(-scan b op x axis reverse?)`: Inclusive scan along axis. op is one of
  :cumsum :cumprod :cummax :cummin.
- `(-scatter-add b x indices updates axis)`: x with updates added at indices
  along axis, accumulating repeats: the transpose of take-along-axis. indices
  (an int array) and updates have one shape, equal to x's on every axis but
  axis.
- `(-shape b x)`: Shape of x as a vector of longs; \[] for 0-d.
- `(-slice b x starts stops steps)`: Strided slice; starts, stops and steps are
  vectors with one entry per axis.
- `(-take b x indices axis)`: Gather: the result's axis is replaced by the
  shape of indices (an int array).
- `(-take-along-axis b x indices axis)`: Gather with indices broadcast against
  x on every other axis.
- `(-to-host b x)`: Host value of x: a number or boolean for 0-d arrays, nested
  vectors otherwise.
- `(-transpose b x perm)`: Permute axes; perm is a vector of all axes.
- `(-value-and-grad b f args argnums)`: Call f on args (a vector) and return
  \[value grads], where grads holds the gradient of the scalar value with
  respect to each position in argnums.
- `IArray` (protocol: `-backend`)
- `IBackend` (protocol: `-arange`, `-astype`, `-broadcast-to`, `-concatenate`,
  `-defaults`, `-dtype`, `-elementwise`, `-eval!`, `-from-host`, `-full`,
  `-lazy?`, `-linalg`, `-matmul`, `-name`, `-native-ops`, `-random-uniform`,
  `-reduce`, `-reshape`, `-scan`, `-scatter-add`, `-shape`, `-slice`, `-take`,
  `-take-along-axis`, `-to-host`, `-transpose`, `-value-and-grad`)
- `IBatchedValue` (protocol: `-all-particles`): A value that holds one value
  per particle of a batch (gen.array.batch).
- `ICompiling` (protocol: `-compile`): A backend that compiles functions of its
  arrays (MLX: mlx_compile).
- `ICustomVjp` (protocol: `-custom-vjp`): A backend that differentiates through
  a function by a VJP it is given (gen.array/custom-vjp): the tape, and MLX in
  native mode.
- `INativeGrad` (protocol: `-native-grad?`): A backend whose -value-and-grad
  differentiates by its own transformation (MLX's mlx_value_and_grad), calling
  f with arrays of its own rather than with gen.array.tape's tracked values.
- `ITrackedValue` (protocol: `-primal`): A value being differentiated on a tape
  (gen.array.tape), which gen.array recognizes without depending on the tape.
- `IWrappingBackend` (protocol: `-inner`): A backend whose arrays build on
  another backend's, such as the tape of reverse-mode autodiff: an op mixing
  its arrays with the inner backend's runs on the wrapping backend.
- `lazy-backends?`: true once a lazy backend (-lazy? true) has been made: a
  backend sets it, so that gen.array/eval! walks nothing where all are eager.

### gen.random

Purely functional randomness. Keys are immutable values and every sampler is a
pure function of its key: the same key gives the same draw.

- `(bernoulli key p)`, `(bernoulli key p shape)`, `(bernoulli key p shape
  opts)`: Bool values, true with probability p (an array or number). shape
  defaults to p's shape.
- `(categorical key logits)`, `(categorical key logits shape)`, `(categorical
  key logits shape opts)`: Index values drawn from the unnormalized
  log-probabilities along the last axis of logits (the Gumbel-max trick, as
  JAX). shape defaults to the batch shape of logits (all but the last axis) and
  must broadcast with it.
- `(exponential key)`, `(exponential key shape)`, `(exponential key shape
  opts)`: Standard exponential values of shape: -log1p(-u) (as JAX).
- `(fold-in k data)`: A new key from k and a non-negative integer (64 bits),
  e.g. to derive one key per address: (split k n)'s key at index data, for
  every n past it.
- `(gamma key alpha)`, `(gamma key alpha shape)`, `(gamma key alpha shape
  opts)`: Gamma(alpha, 1) values of shape (default: alpha's shape), by
  Marsaglia–Tsang with a fixed number of vectorized proposal rounds (no
  data-dependent loop), boosting alpha < 1 as Γ(α) = Γ(α+1)·U\^(1/α).
- `(gumbel key)`, `(gumbel key shape)`, `(gumbel key shape opts)`: Standard
  Gumbel values of shape: -log(-log u), u uniform on \[tiny, 1) (as JAX).
- `(key seed)`: The key for an integer seed (as JAX's PRNGKey).
- `(key-data k)`: The two uint32 words of a key.
- `(key? x)`
- `(normal key)`, `(normal key shape)`, `(normal key shape opts)`: Standard
  normal values of shape: √2·erfinv(u), u uniform on \[nextafter(-1, 0), 1) (as
  JAX).
- `(randint key low high)`, `(randint key low high shape)`, `(randint key low
  high shape opts)`: Integers uniform in \[low, high) of shape (default \[]).
- `(split k)`, `(split k n)`: n new, independent keys from k (two by default).
- `(uniform key)`, `(uniform key shape)`, `(uniform key shape opts)`: Uniform
  values in \[low, high) of shape (default \[], a host number on the JVM
  backend).

## Choice maps, selections, traces and diffs

### gen.choicemap

Choice maps: hierarchical maps from addresses to the values of random choices.
A choice map is a Node (a persistent map from address to child) or a Value (a
leaf holding one choice); they are plain Clojure data with a thin protocol, so
equality, hashing and structural sharing come for free.

- `(->Value v)`: Positional factory function for class Value.

- `EMPTY`
- `IChoiceMap` (protocol: `-get-submap`, `-get-value`, `-has-value?`,
  `-submaps`)
- `(addresses cm)`: Every leaf path, in canonical order.
- `(choicemap & kvs)`: A choice map from address-value pairs.
- `(choicemap? x)`: Is x a choice map (a Value or a Node)?
- `(empty? cm)`: Does the choice map hold no values?
- `(from-array proto arr)`: A choice map with the addresses, leaf shapes and
  leaf dtypes of proto, filled in order from the 1-d array arr (the inverse of
  to-array, which concatenates into one dtype: a bool choice comes back a
  bool).
- `(from-map m)`: A choice map from a nested Clojure map: plain maps become
  nodes, a choice map stays itself, anything else is a leaf.
- `(get-choice cm addr)`, `(get-choice cm addr not-found)`: The value at an
  address or path.
- `(get-submap cm addr)`, `(get-submap cm addr not-found)`: The choice map at
  an address or path: a node, a value (a choice map too), or EMPTY when nothing
  is there.
- `(get-value cm)`, `(get-value cm not-found)`: The value of a value choice map
  (a leaf).

  value, or hold one at the address or path?
- `(leaves cm)`: Every leaf as \[path value], in canonical address order: one
  depth-first walk.
- `(map->Node m)`: Factory function for class Node, taking a map of keywords to
  field values.
- `(map->Value m)`: Factory function for class Value, taking a map of keywords
  to field values.
- `(merge)`, `(merge x)`, `(merge x y)`, `(merge x y & more)`: The union of
  choice maps whose addresses are disjoint (Gen.jl's merge; EMPTY of none).

  whole subtree; an empty y leaves x (a value too) as it is.

  and b under key-b.
- `(path addr)`: The path of an address or a path: \[addr] for an address, a

  without the nodes that leaves empty (at the empty path, EMPTY).
- `(remove-submap cm addr)`: cm without anything at a single address (a path is
  an error).
- `(set-choice cm addr v)`: cm with value v (a leaf value or a choice map) at
  an address or path; at the empty path, v is the whole choice map.
- `(set-submap cm addr sub)`: cm with the choice map sub at an address or path,
  as get-submap reads it (Gen.jl's set_submap!).
- `(set-value cm addr v)`: cm with the leaf value v at a single address, of a
  node (or nil); a path is an error: set-choice takes paths.
- `(stack cms)`: Stack choice maps with identical addresses into one whose
  leaves have a new leading axis (the batch of particles).
- `(submaps cm)`: The \[address child] pairs of a node, in canonical address
  order.
- `(submaps-shallow cm)`: The \[address choice-map] pairs of the nodes directly
  under the top of cm (Gen.jl's get_submaps_shallow), in canonical order.
- `(to-array cm)`: Every leaf, flattened and concatenated in canonical address
  order, as one 1-d array (Gen.jl's to_array).
- `(to-map cm)`: The choice map as a nested Clojure map of values.
- `(unpair c key-a key-b)`: Gen.jl's unpair: \[the submap at key-a, the submap
  at key-b] of c, which must hold nothing else.
- `(unstack cm n)`: Split a choice map whose leaves have a leading batch axis
  of size n into n choice maps (the inverse of stack).
- `(values cm)`: Every leaf value, in the canonical order of addresses.
- `(values-shallow cm)`: The \[address value] pairs directly at the top of a
  node (Gen.jl's get_values_shallow), in canonical order.

## The generative function interface

### gen.batched

N particles of a generative function at once. A particle collection runs the
model's code once for all n particles, under the batch tracer
(gen.array.batch): the code sees per-particle values, every op acts per
particle and every draw is independent per particle, so the per-site handler
cost is paid once rather than n times.

- `*required*` (dynamic): When true, a batched run that cannot run batched
  throws ex-info with the reason it would have fallen back for (its message,
  and :fallback in its data) in place of falling back to one particle at a
  time: what :batched? :required binds (gen.inference.importance,
  gen.inference.particle-filter, …; DESIGN.md §9, the ten decisions' ninth).
  false by default: the run falls back, and records why.
- `*spot-checks*` (dynamic): How many evenly spaced particles of a batched run
  are verified against the scalar handler: a number (8), :all, or 0 for none.
- `*verified-updates*` (dynamic): Updates and regenerates of a collection are
  spot-checked on a schedule: the first \*verified-updates\* (2), then the 4th,
  8th, 16th and so on.
- `(->Particles n gen-fn args trace traces)`: Positional factory function for
  class Particles.
- `(->Read batched? v dtype host)`: Positional factory function for class Read.
- `(batched? ps)`: Does ps still hold one batched trace (rather than the
  per-particle fallback)?
- `(check ps)`: ps, verified: when operations since its last spot check went
  unchecked (\*verified-updates\*), the trace they left is spot-checked now,
  against the generative function that made it (particles may since have been
  given another, review 7, R7-3), and a mismatch is the loud divergence error.
- `(choice ps addr)`: The choice at addr across the particles, as an \[n …]
  array: through a Switch whose index differs across them when every particle
  makes it.
- `(fallback ps)`: Why ps fell back to per-particle traces, a written message,
  or nil while it runs batched.
- `(fallback-reason ps)`: Why ps fell back to per-particle traces: {:message
  (fallback ps) :data (the failure's ex-data)}, or nil.
- `(generate gf args constraints n key)`, `(generate gf args constraints n key
  opts)`: n particles of gf on args with the shared constraints, and their
  weights.
- `(map->Particles m)`: Factory function for class Particles, taking a map of
  keywords to field values.
- `(map-particles ps f key & xs)`: (f trace key x …) of every particle at once,
  as vmap's: each x a tree of arrays with the leading particle axis, of which a
  particle is given its own rows.
- `(map-particles* ps f key & xs)`: map-particles' {:result (f's results,
  stacked) :fallback (why f ran on each trace, a written message, or nil)}, for
  the kernels that run f (gen.inference.mcmc's -particles kernels,
  gen.gradients), which record it in their results.
- `(move ps f key & xs)`: Every particle's trace moved by f, (f trace key x …)
  → {:trace trace' …}, at once: an MCMC move run batched, as map-particles runs
  a function.
- `(particles? x)`
- `(project ps selection)`: The particles' log densities of the selected
  choices (gfi/project), an \[n] array: the batched trace's projection under
  the batch tracer, or each particle's when that fails (a projection that runs
  code which cannot treat the particles alike), which \*required\* refuses.
- `(project* ps selection)`: project's {:result (the \[n] array) :fallback (why
  it ran each particle's projection, a written message, or nil)}.
- `(refused e)`: The error of a batched run that failed (e) where \*required\*
  refuses the fallback to one particle at a time, naming why.
- `(regenerate ps args argdiffs selection key)`: Every particle with the
  selection regenerated, at args.
- `(scores ps)`: The particles' log densities, an \[n] array.
- `(select mask ps qs)`: ps's particle where mask (n booleans, or a bool array)
  is true and qs's elsewhere: the per-particle accept step of n MH chains.
- `(set-choices ps choices)`: The particles with their choices at the addresses
  of choices set, each particle's to its own value (choices' leaves have the
  leading particle axis), every other choice kept: each trace remade from its
  choices by the generative function that made it (gfi/update, where ps holds
  per-particle traces).
- `(simulate gf args n key)`: n particles of gf on args.
- `(size ps)`
- `(take ps indices)`: The particles at indices (a seq of n' integers), e.g.
  after resampling: every batched value of the trace gathered there, lazily, so
  a resampled trace is made without re-running the model
  (gen.partition/gather).
- `(traces ps)`: The n scalar traces, each rebuilt exactly from its particle's
  choices (after check) by the generative function that made them, and given
  the particles' :gen-fn: particles given another gen-fn, (assoc ps :gen-fn g),
  hold traces given g, which an update or regenerate revises (gfi/revise), per
  particle as when batched (review 6, R6-2).
- `(update ps args argdiffs constraints key)`, `(update ps args argdiffs
  constraints key opts)`: Every particle updated to args with the shared
  constraints.
- `(written e)`: The reason a batched run failed, e, as a written message: an
  ex-info's own (gen.clj's errors are written ones: a branch on a value that
  differs across particles, a failed spot check, a parameter's check); host
  math on a batched value, which Java's cast rejects, said so; any other
  exception named with its class.

### gen.dynamic

The dynamic modeling language: generative functions written as Clojure code
with the gen macro.

- `*params*` (dynamic): The trainable parameters in effect: the store of the
  outermost generative function that has one, merged with any inner one's
  (with-params).
- `(->DynamicGF body-fn source params transitions dispatch static)`: Positional
  factory function for class DynamicGF.
- `(defn-guarded fname & more)` (macro): defn with guarded-fn's guards:
  (defn-guarded name doc? \[params] body…).
- `(dynamic-gf? x)`
- `(gen params & body)` (macro): A generative function. params are the
  arguments (destructuring allowed); in body, (trace addr dist) and (splice
  addr gf & args) make random choices and calls, (param name) reads a trainable
  parameter (with-params), and conditionals branch on the values of 0-d arrays.
- `(guarded-fn & fn-tail)` (macro): fn, with a gen body's guards: if and case
  tests branch through truthy?, catch clauses raise the fallback in a batched
  run, and clojure.core's truthiness, lookup and type tests are
  gen.dynamic.core's.
- `(make-gen-fn body-fn source)`, `(make-gen-fn body-fn source static)`: A
  dynamic generative function from a body fn of (trace splice param untraced &
  args) and its source form, and optionally the graph of a static body (the gen
  macro's, gen.dynamic.static).
- `(map->DynamicGF m)`: Factory function for class DynamicGF, taking a map of
  keywords to field values.
- `site-transitions`: The standard handler transitions, one per operation: (fn
  \[state path dist key] → \[value state']).
- `(with-dispatch gf dispatch)`: gf with an execution seam: (dispatch gf op
  args opts) runs before the handler and returns the operation's result map, or
  nil to leave it to the handler (opts: :key, and per operation :constraints,
  :prev and :selection; a batched run calls the dispatcher under the batch
  tracer, where (gen.array.batch/batch-backend? gen.array/\*backend\*) holds).
- `(with-params gf params)`: gf with the trainable-parameter store params, a
  map of name to value read by (param name) in gf's body and in every
  generative function it calls. gf is a dynamic generative function: the store
  is the body's (another kind reads the store of the dynamic function that
  calls it; a deterministic function that names :params may have its own,
  gen.custom/with-params).
- `(with-transitions gf transitions)`: gf, a dynamic generative function, with
  handler middleware: a map from operation (:simulate :generate :assess :update
  :regenerate) to a transition (fn \[state path dist key] → \[value state'])
  used in place of the standard one (site-transitions), typically by wrapping
  it.

### gen.gfi

The Generative Function Interface, shaped like Gen.jl's.

*For implementers:* IGenerativeFunction, IRevisable and IStores, which a new
kind of generative function implements.

- `*exact-density*` (dynamic): The name of the operation in effect that needs
  exact densities (a gradient, an exact enumeration, a replayed proposal), or
  nil.
- `(-assess gf args choices key)`
- `(-generate gf args constraints key)`
- `(-project gf trace selection)`
- `(-propose gf args key)`
- `(-regenerate gf trace args argdiffs selection key)`
- `(-revise gf op args opts project-old)`: op (:update or :regenerate, opts as
  run-op's) of (:prev opts), a trace gf may not have made: revise's result.
  (project-old prev selection) is prev's projection under the context prev ran
  in.
- `(-same-gen-fn? gf other budget)`: Does gf compute as other, a generative
  function of gf's class? budget as same-value?'s.
- `(-simulate gf args key)`
- `(-stores gf)`: gf's stores, or nil: a store is a map of name to value, and a
  combinator's are in the shape of its callees.
- `(-update gf trace args argdiffs constraints key)`
- `(-with-stores gf stores)`: gf holding stores, in -stores' shape, in place of
  its own.
- `IGenerativeFunction` (protocol: `-assess`, `-generate`, `-project`,
  `-propose`, `-regenerate`, `-simulate`, `-update`)
- `IRevisable` (protocol: `-revise`, `-same-gen-fn?`): How a generative
  function stands to traces it may not have made.
- `IStores` (protocol: `-stores`, `-with-stores`): The stores of trainable
  parameters a generative function holds, as gen.gradients/param-gradients
  differentiates and gen.learning steps them: a dynamic or deterministic
  function's own (with-params), and a combinator's callees'.
- `(assess gf args choices)`, `(assess gf args choices key)`: The log density
  of fully specified choices, and the return value.
- `(assess-backward t t' q args u' k)`: A move's backward weight: the backward
  proposal q, called on (t' args…), assesses u', the choices that reverse the
  move from trace t to t', with (backward-key k); {:weight :retval}, as assess.
- `(backward-key k)`: A key for a move's backward assess, folded from the
  move's key k apart from any key a generative function derives from k (sites
  split it, Map and Unfold fold it with small element indices), so encapsulated
  randomness there never repeats the model's.
- `(check-argdiffs op args argdiffs)`: One argdiff per argument: a missing one
  would silently mean no-change.
- `(check-args op args)`: The arguments as a vector: they must be a sequential
  collection (or nil, no arguments).
- `(check-choice-map op what x)`: x, a choice map (nil is the empty one).
- `(check-exact-density! what)`: Throws when an operation that needs exact
  densities is in effect: what (an untraced draw, an estimated density) makes
  the score an estimate.
- `(check-selection op x)`: x, a selection.
- `(defgf name fields & impls)` (macro): defrecord, for a generative function,
  plus untraced calls as in Gen.jl: (gf a b …), with any number of arguments,
  is the return value of a simulated run (untraced-call: in a running body with
  a key from its encapsulated randomness, elsewhere from the implicit source).
- `(eval-trace! tr)`, `(eval-trace! tr also)`: Force the evaluation of tr's
  arrays (choices, return value and score) on a lazy backend, and return tr.
- `(generate gf args constraints)`, `(generate gf args constraints key)`: A
  trace of gf on args consistent with constraints (a choice map), and the log
  weight log p(τ; x) - log q(υ; x, σ), where υ are the choices the internal
  proposal sampled and σ the constraints.
- `(generate-again gf op args {:keys [prev constraints selection key]}
  project-old)`: op (:update or :regenerate, opts as run-op's) of prev, (:prev
  opts), as generate from prev's choices: update's (prev's choices overridden
  by the constraints) or regenerate's (the unselected ones).
- `(generative-function? x)`: Does x implement the GFI?
- `(implicit-seed)`: The seed of the implicit key source: random for each JVM
  unless seed! set it.
- `(impossible? x)`: Is x, a log density, score or weight, -Inf on the host?
- `(next-key)`: A fresh key from the implicit key source (deterministic given
  the seed and the order of calls).
- `(project trace selection)`: The log density of the selected choices of a
  trace, by the generative function that made it (as Gen.jl's project
  dispatches on the trace's type): a trace given another :gen-fn is still read
  by its maker.
- `(project-by-maker tr selection)`: tr's projection on selection by its maker:
  project without its check of the selection.
- `(propose gf args)`, `(propose gf args key)`: Sample choices from gf, with
  their log density and the return value.
- `(regenerate trace selection)`, `(regenerate trace selection key)`,
  `(regenerate trace args argdiffs selection)`, `(regenerate trace args
  argdiffs selection key)`: The trace with new arguments and the selected
  choices resampled from the internal proposal.
- `(revise gf op args opts)`, `(revise gf op args opts project-old)`: op
  (:update or :regenerate, opts as run-op's) of (:prev opts), a trace gf did
  not make or that ran in another context (a call's changed store): nothing of
  it is kept but its choices, whatever kind gf is (no argument shows such a
  change, so no kind's own skipping could see it).
- `(run-op gf op args opts)`: Run a GFI op on gf from a map of its inputs (:key
  :constraints :prev :argdiffs :selection).
- `(same-gen-fn? a b)`: Do generative functions a and b compute the same:
  identical, or of one class and the same by their kind's rule (IRevisable; a
  record's fields the same values, same-value?)?
- `(same-value? a b)`, `(same-value? a b budget)`: Are a and b the same value,
  judged without reading an array (a host read inside a run) and as code
  holding them could tell (review 6, R6-1)?
- `(seed! seed)`: Reset the implicit key source to seed: later calls without a
  key repeat exactly.
- `(simulate gf args)`, `(simulate gf args key)`: Sample a trace of gf on args.
- `(stores gf)`: The trainable-parameter stores gf holds, or nil: a dynamic or
  deterministic function's own store (a map of name to value); a Map's or an
  Unfold's, its kernel's; a Switch's, {branch stores} over the branches that
  hold some; a Recurse's, {:production stores :aggregation stores} over those
  that do.
- `(under e at)`: e, raised inside a call at path at (the call's address in its
  caller), with its unvisited paths under at; any other error is e itself.
- `(unvisited op paths)`, `(unvisited op paths detail)`: The error for
  constraints at paths (relative to the generative function whose run left them
  unvisited) that a run did not visit, flagged for the calls above and for
  revise: ex-data :unvisited, :paths and :path (the first). detail, if given,
  follows the message in parentheses.
- `(update trace constraints)`, `(update trace constraints key)`, `(update
  trace args argdiffs constraints)`, `(update trace args argdiffs constraints
  key)`: The trace with new arguments and constrained choices.
- `(with-exact-density op & body)` (macro): body, in which encapsulated
  randomness is an error naming op.
- `(with-stores gf stores)`: gf holding stores, in the shape (stores gf) gives,
  as gen.learning's step returns them.

### gen.laws

The GFI's laws (Cusumano-Towner 2020; docs/research/genjl-parity.md §3, audited
in docs/research/law-audit.md) as test.check properties over any generative
functions, and the means to run them on yours.

*In ext/laws,* a module beside the core with dependencies of its own.

- `across`: For pairs of generative functions: models \[label gf args alt-args
  gf'], gf' typically gf under another store (gen.dynamic/with-params).
- `all`: general and forward-sampling: the laws of a generative function that
  samples forward, verify's and deflaws' default.
- `(assess-is-generate-with-every-choice cases)`: assess's weight is generate's
  on the same choices and key: the key draws the same encapsulated randomness
  in both (§4.5.1).
- `(cases models)`: A test.check generator of cases \[\[label gf args alt-args]
  seed picks alt?] over models: a vector of model entries, or a generator of
  them (e.g. random models).
- `(check property)`, `(check num-tests property & opts)`: quick-check of a
  law's property over num-tests cases (100 by default), with the count of its
  vacuous cases as :vacuous: a law more than :max-vacuous (max-vacuous by
  default) of whose cases were vacuous fails, its :result-data {:vacuous :of
  :max-vacuous}.
- `(checks & forms)` (macro): and over a law's checks, as a test.check result:
  true when every check passes, vacuous when every one was vacuous, and
  otherwise a failure naming the first that failed, as its form (:check), with
  the values of its arguments (:values) when it is a function call.
- `(close? x y)`: Are weights x and y equal within the backend's precision?
- `(deflaws prefix models opts)`, `(deflaws prefix models opts laws)` (macro):
  A test.check spec per law of laws (all by default), named prefix-law, each
  over cases of models, with prefix's metadata (\^:slow, say), run by check.
  opts is the number of cases, or a map of it (:num-tests) and check's options.
  laws is evaluated when the deflaws compiles: a law set's var, a map, or an
  expression of them, such as (merge laws/all laws/fixed-support).
- `(dispatch-matches-handler cases)`: A dispatcher (gen.dynamic/with-dispatch)
  is observationally equivalent to the handler: each operation gives the same
  choices, weights and return values with the same key.
- `encapsulated`: The laws of a generative function with encapsulated
  randomness ω, whose score is an estimate: those of general and
  forward-sampling that hold for one ω, and the others without their
  comparisons of separate runs (assess against a trace's score, propose against
  assess, an update and its reverse), which hold only in expectation (Eqs.
  4.3-4.4, tested statistically).
- `estimated`: The laws of an estimated density with a joint sampler
  (gen.custom/estimated with :simulate, or a model that calls one):
  encapsulated without score-is-assessed-on-the-same-key.
- `(failure-of r)`: What check's failing result r says, readably: the failing
  check's :check and :values (or what its explain gives), or the :error thrown
  (its message, ex-data as :data, and the :exception), or the counts of a law
  that failed for its vacuous cases; with the smallest failing case test.check
  shrank it to (:case, {:model :key-seed :picks :alt?}: the model by its label,
  the seed of the case's keys, as cases has them), and the run's :seed,
  test.check's.
- `fixed-support`: For models whose every address has a fixed support.
- `forward-sampling`: The laws of a generative function whose internal proposal
  samples the unconstrained choices from the prior, each site from its own key,
  as gen and the combinators do.
- `general`: The laws of every generative function: the thesis's definitions
  (Def 2.1.16's trace consistency, Def 2.3.1's update and discard, Prop 2.3.1's
  reversibility, Def 2.3.2's retdiffs, Eq 4.1's regenerate weight), for any
  internal proposal.
- `(generate-weight-is-the-constrained-density cases)`: Forward sampling:
  generate's weight is the log density of the constrained choices, and the open
  ones are drawn as simulate draws them on the same key.
- `(generate-weight-is-the-projection cases)`: generate's weight given sigma is
  the projection of its trace on sigma's addresses: both are log p(τ)/q(τ∖σ |
  σ), q the internal proposal, whatever it is (forward sampling, an exact or a
  custom proposal).
- `(generate-weights-are-finite-on-a-fixed-support cases)`: Def. 4.1.1's
  support condition, for a model whose every address has a fixed support
  (thesis pp. 169-170): constraints drawn from a simulated trace are in the
  support, so the trace's score and generate's weight are finite (law audit gap
  E: not-NaN let a -Inf weight pass).
- `(generate-with-every-choice-is-deterministic cases)`: generate constrained
  on every choice of a trace makes those choices, with the trace's score as its
  weight.
- `(generate-with-every-choice-weighs-its-score cases)`: Encapsulated
  randomness: generate constrained on every choice of a trace makes those
  choices, its weight the score of the trace it makes.
- `(generate-without-constraints-has-weight-zero cases)`: Forward sampling:
  generate without constraints has weight 0.
- `(generated-traces-are-consistent cases)`: generate constrained on some of a
  trace's choices keeps them and makes a consistent trace, and its weight is
  not NaN.
- `(generated-traces-keep-their-constraints cases)`: Encapsulated randomness:
  generate keeps its constraints, and its weight is not NaN.
- `(identity-update-changes-nothing cases)`: An update without constraints has
  weight 0, keeps every choice, discards nothing, and reports a sound change of
  its return value.
- `(identity-update-keeps-omega cases)`: An update that changes nothing keeps ω
  and the score (DESIGN.md §9).
- `(identity-update-reports-no-change cases)`: An implementation property, not
  a thesis law (Def 2.3.2 allows unknown-change): an identity update's retdiff
  is no-change.
- `implementation`: Properties of gen.clj's own generative functions that the
  thesis does not require: an identity update reports no-change (unless its
  return value holds an array), so that a caller can skip work.
- `max-vacuous`: The share of a law's cases that may be vacuous before check
  fails it.
- `(project-of-everything-is-the-score cases)`: A trace projected on every
  address gives its score.
- `(project-splits-the-score cases)`: project splits the score over a partition
  of the choices: none projects to zero, and a selection and its complement add
  up to the score; so do two disjoint selections s and t, their union, and the
  rest, by De Morgan's law the intersection of their complements.
- `(propose-weight-is-the-assessed-density cases)`: propose's weight is the
  density assess gives the choices it proposed.
- `(regenerate-across-generative-functions cases)`: A regenerate of a trace
  that gf made, given gf': the unselected choices are kept, and the weight is
  Eq. 4.1's with each trace projected by its own generative function, on the
  retained choices.
- `(regenerate-keeps-unselected-choices cases)`: regenerate makes a consistent
  trace and keeps every unselected choice.
- `(regenerate-keeps-unselected-values cases)`: Encapsulated randomness:
  regenerate keeps every unselected choice and reports a sound change of its
  return value.
- `(regenerate-weight-is-the-projection-ratio cases)`: regenerate's weight is
  the ratio of the projections of the new and the old trace on the retained
  choices (Eq. 4.1): with forward sampling, the retained density ratio; for any
  internal proposal, its correction.
- `(regenerate-weight-is-the-retained-density-ratio cases)`: Forward sampling:
  regenerate's weight is the log density ratio of the retained choices (Eq 4.1,
  Alg 18).
- `(regenerate-weight-with-new-arguments-is-the-projection-ratio cases)`: Eq.
  4.1 with new arguments (p. 144): the projection of the new trace, on the new
  arguments, on the retained choices, less the old trace's on its own arguments
  (the reverse move generates at the old arguments: the thesis's Alg. 16 reads
  x' there, an erratum).
- `(regenerating-everything-has-weight-zero cases)`: Forward sampling: a
  regenerate of every choice has weight 0.
- `(regenerating-nothing-changes-nothing cases)`: A regenerate with nothing
  selected has weight 0 and keeps the choices.
- `(runs-are-pure-functions-of-the-key cases)`: The same key makes the same
  choices.
- `(score-is-assessed-on-the-same-key cases)`: Def 2.1.16 pointwise for
  untraced draws: simulate and assess on one key draw the same ω, so the score
  is assess's weight (law audit gap 12).
- `(score-is-the-assessed-density cases)`: Trace consistency (Def 2.1.16): a
  simulated trace's score is the density assess gives its choices, and the
  return values agree.
- `seeds`: The seeds of the cases' keys, any of 2\^31. gen/nat is bounded by
  test.check's size, so a run of 100 cases drew its keys from 0-99, half of
  them twice, and every run the same ones (2026-10-24).
- `static`: For a static generative function (gen \^:static).
- `(static-matches-dynamic cases)`: The static language is an optimization of
  the dynamic one (DESIGN.md §9): every operation on a static gf gives what the
  same body without \^:static gives under the same keys (choices, scores,
  weights, return values and discards, and a sound retdiff), also when an
  update or regenerate skips nodes (no-change argdiffs for unchanged
  arguments).
- `(unvisitable? e)`: Is e an error for constraints drawn from another run that
  this run cannot visit (a structural mismatch the GFI correctly rejects)?
- `(update-across-generative-functions cases)`: An update of a trace that gf
  made, given gf' (another generative function, such as gf under another
  store): only its choices are kept (gfi/revise), so Def. 2.3.1 holds against
  gf': the new trace is gf''s, the weight is log p'(τ') - log q'(fresh | the
  rest) - log p(τ) (the projection of τ' on its kept choices, less τ's score),
  the discard is the old choices constrained or gone, and updating back with gf
  and the discard restores τ, the two weights adding to -log q'(fresh) (law
  audit F5: store-test had examples only).
- `(update-weight-is-the-projection-change cases)`: update's weight is the
  projection of the new trace on its choices that are not fresh (kept from the
  old trace or constrained), less the old score: log p(τ')/q(fresh | the
  rest) - log p(τ) (Def. 2.3.1, p. 69, with an internal proposal), whatever the
  proposal.
- `(update-weight-is-the-score-change-less-fresh cases)`: Encapsulated
  randomness: update's weight is the change of score less the log density of
  the choices drawn afresh, for one draw of ω.
- `(update-weight-is-the-score-change-less-fresh-choices cases)`: Forward
  sampling: update's weight is the change of score less the log density of the
  choices drawn afresh, and an update back adds the negated fresh density to
  it.
- `(updates-and-regenerates-keep-the-assessed-score cases)`: Def 2.1.16 after
  chains of moves: a trace updated to other arguments and constraints and back
  with its discard, and one regenerated to other arguments and back, has the
  assessed density of its choices as its score.
- `(updates-are-reversible-with-exact-discards cases)`: An update with
  constraints from another run, on other arguments, makes a consistent trace
  whose discard is Def 2.3.1's, and updating back with the discard restores the
  trace (Prop 2.3.1).
- `(updates-restore-their-choices cases)`: Prop 2.3.1 for the choices: the
  discards of an update, given back, restore them (the weights agree only in
  expectation).
- `vacuous`: The result of a case a law says nothing about: it passes, and
  check and deflaws count it.
- `(vacuous-on-unvisitable & body)` (macro): body's value, or vacuous when body
  throws an ex-info that unvisitable? says is an unvisitable constraint (any
  other error is thrown): for an operation given constraints from another run.
- `(vacuous? r)`: Is r a vacuous case's result?
- `(verify models)`, `(verify models opts)`, `(verify models opts laws)`: Runs
  every law of laws (all by default) over cases of models, and returns the
  failures: a sorted map from each law that failed to what it says (failure-of:
  the check that failed and the values it compared, or the error thrown, the
  smallest failing case and the run's seed); {} when every law holds. opts is
  the number of cases of each law (100 by default), or a map of it (:num-tests)
  and check's options: :seed, :max-size and :max-vacuous.

- `(->Written form)`: Positional factory function for class Written.

- `(read-trace-data s)`: The parts of the written trace s (write-trace's text),

## Distributions

### gen.dist

Gen.jl's built-in distributions, with Gen.jl's names and parameterizations
(normal by standard deviation, gamma by scale, categorical by probabilities),
plus categorical-logits, and further continuous families with
Distributions.jl's names and parameters (chi-squared, f-dist, gumbel, levy,
log-normal, logistic, nakagami, pareto, student-t, triangular, weibull;
truncated-normal, von-mises, wishart, inv-wishart), and the wrapped circular
families with scipy's (wrapped-cauchy, wrapped-normal). Discrete values are
0-based integers; bernoulli values are booleans; circular values are angles in
\[-π, π).

- `(bernoulli p)`: bernoulli(prob): true with probability prob.
- `(beta a b)`: beta(alpha, beta): the beta distribution on \[0, 1].
- `(beta-uniform theta a b)`: beta_uniform(theta, alpha, beta): with
  probability theta a beta(alpha, beta) draw, otherwise a uniform draw on \[0,
  1].
- `(binom n p)`: binom(n, p): the number of successes in n trials with success
  probability p.
- `broadcasted-normal`: broadcasted_normal(mu, std): normal with broadcast
  array parameters (in gen.clj, normal itself already broadcasts).
- `(categorical probs)`: categorical(probs): index i (0-based) with probability
  probs\[i]; probs must be probabilities (see categorical-logits for logits).
- `(categorical-logits logits)`: categorical-logits(logits): index i (0-based)
  with probability softmax(logits)\[i].
- `(cauchy x0 scale)`: cauchy(x0, gamma): the Cauchy distribution with location
  x0 and scale gamma.
- `(chi-squared nu)`: chi-squared(nu): the χ² distribution with nu degrees of
  freedom (Chisq).
- `(dirichlet alpha)`: dirichlet(alpha): the Dirichlet distribution over the
  simplex of the last axis of alpha.
- `(exponential rate)`: exponential(rate): the exponential distribution with
  mean 1/rate.
- `(f-dist nu1 nu2)`: f-dist(nu1, nu2): Fisher's F distribution, the ratio of
  χ² draws over their degrees of freedom (FDist).
- `(gamma k theta)`: gamma(shape, scale): the gamma distribution with mean
  shape·scale.
- `(geometric p)`: geometric(p): the number of failures before the first
  success.
- `(gumbel mu theta)`: gumbel(mu, theta): the Gumbel (maximum) distribution,
  location mu and scale theta (Gumbel).
- `(heterogeneous-mixture families)`: A family of mixtures of different
  distribution families (Gen.jl's HeterogeneousMixture):
  ((heterogeneous-mixture \[normal uniform]) weights \[mu std] \[low high])
  mixes (normal mu std) and (uniform low high).
- `(homogeneous-mixture family)`, `(homogeneous-mixture family dims)`: A family
  of mixtures of one distribution family (Gen.jl's HomogeneousMixture):
  ((homogeneous-mixture normal) weights mus stds) mixes (normal (mus k) (stds
  k)). dims, as Gen.jl's, gives each parameter's rank in one component (0 by
  default); the axis before those indexes the components, so
  ((homogeneous-mixture mvnormal \[1 2]) weights mus covs) takes mus of shape
  \[K d] and covs of shape \[K d d].
- `(inv-gamma k theta)`: inv_gamma(shape, scale): the inverse gamma
  distribution (1/X for X with gamma(shape, 1/scale)).
- `(inv-wishart df scale)`: inv-wishart(df, scale): the inverse Wishart
  distribution over p×p symmetric positive definite matrices (InverseWishart(ν,
  Ψ)), the law of W⁻¹ for W with wishart(df, scale⁻¹); its mean is scale/(df -
  p - 1) for df > p + 1.
- `(laplace loc scale)`: laplace(loc, scale): the Laplace (double exponential)
  distribution.
- `(levy mu sigma)`: levy(mu, sigma): the Lévy distribution, location mu and
  scale sigma, mu + sigma/Z² for a standard normal Z (Levy).
- `(log-normal mu sigma)`: log-normal(mu, sigma): e\^X for X normal(mu, sigma)
  (LogNormal).
- `(logistic mu theta)`: logistic(mu, theta): the logistic distribution,
  location mu and scale theta (Logistic).
- `(mvnormal mu cov)`: mvnormal(mu, cov): the multivariate normal with mean
  vector mu and covariance matrix cov (batched over leading axes).
- `(nakagami m omega)`: nakagami(m, omega): the Nakagami distribution, shape m
  and spread omega, the root of a gamma(m, omega/m) draw (Nakagami; m > 0, as
  Distributions.jl's, where Commons Math asks m >= 1/2).
- `(neg-binom r p)`: neg_binom(r, p): the number of failures before the r-th
  success (r may be real).
- `(normal mu std)`: normal(mu, std): the Gaussian with mean mu and standard
  deviation std.
- `(pareto alpha theta)`: pareto(alpha, theta): the Pareto distribution, shape
  alpha and scale (minimum) theta (Pareto).
- `(piecewise-uniform bounds probs)`: piecewise_uniform(bounds, probs): bin i,
  chosen with probability probs\[i], is \[bounds\[i], bounds\[i+1]], uniform
  within the bin.
- `(poisson lam)`: poisson(lambda): the Poisson distribution with mean lambda.
- `(product & families)`: A family of products of independent distributions
  (Gen.jl's ProductDistribution): ((product normal bernoulli) \[mu std] \[p])
  has values \[x b], a vector with one value per factor (each of its factor's
  shape).
- `(student-t nu)`: student-t(nu): Student's t distribution with nu degrees of
  freedom, a standard normal over the root of a χ²/nu draw (TDist).
- `(triangular a b c)`: triangular(a, b, c): the triangular distribution on
  \[a, b] with mode c (TriangularDist).
- `(truncated-normal mu sigma lo hi)`: truncated-normal(mu, sigma, lo, hi):
  normal(mu, sigma) conditioned on \[lo, hi] (Distributions.jl's
  truncated(Normal(mu, sigma), lo, hi)); lo must be below hi, and either may be
  infinite.
- `(uniform low high)`: uniform(low, high): uniform on \[low, high].
- `(uniform-discrete low high)`: uniform_discrete(low, high): an integer
  uniform on low..high inclusive.
- `(von-mises mu kappa)`: von-mises(mu, kappa): the von Mises distribution on
  the circle, mean direction mu and concentration kappa > 0 (VonMises), density
  e\^(κ·cos(x - μ))/(2π·I₀(κ)), values in \[-π, π) (Distributions.jl's are in
  \[μ - π, μ + π]: the same density, on another period).
- `(weibull alpha theta)`: weibull(alpha, theta): the Weibull distribution,
  shape alpha and scale theta (Weibull).
- `(wishart df scale)`: wishart(df, scale): the Wishart distribution over p×p
  symmetric positive definite matrices with df degrees of freedom and scale
  matrix S (Wishart(ν, S)), the law of Σᵢ xᵢxᵢᵀ for df draws xᵢ of
  mvnormal(0, S) when df is an integer; its mean is df·S. df must be above p -
  1, and S symmetric positive definite (as mvnormal's covariance); both batch
  over their leading axes.
- `(wrapped-cauchy mu rho)`: wrapped-cauchy(mu, rho): cauchy(mu, -log rho)
  wrapped onto the circle (scipy's wrapcauchy, centered on mu), density (1 -
  ρ²)/(2π·(1 + ρ² - 2ρ·cos(x - μ))), values in \[-π, π); 0 <= rho < 1, and
  rho = 0 is the uniform on the circle.
- `(wrapped-normal mu sigma)`: wrapped-normal(mu, sigma): normal(mu, sigma)
  wrapped onto the circle, density Σₖ N(x + 2πk; μ, σ), values in \[-π, π).

### gen.dist.core

Distributions: one Distribution record (a type keyword and a map of parameters)
with open multimethods, so a distribution can be added from any namespace with
defdist.

- `(->Distribution type params)`: Positional factory function for class
  Distribution.
- `(->array p)`: A parameter given as Clojure data (a vector of numbers) as an
  array.
- `(->checkable p)`: A parameter as validation sees it: Clojure data as a JVM
  backend array, which is always concrete (so host data is checked on every
  backend, also a lazy one); arrays as they are.
- `-discrete?` (multimethod): Does the distribution have discrete values
  (Gen.jl's is_discrete)?
- `-log-prob` (multimethod): The log density (or mass) of value v: (-log-prob d
  v).
- `-pathwise?` (multimethod): Is the distribution's sample a differentiable
  function of its parameters for a fixed key (a reparameterization: noise drawn
  apart from the parameters, then transformed)?
- `-printed-params` (multimethod): A distribution's parameters as it prints
  them: arrays as host data.
- `-sample` (multimethod): Draw a value: (-sample d key batch-shape).
- `-support` (multimethod): The values of a discrete distribution, in order, or
  nil when it has none to enumerate (its values are not finite, or array
  parameters bound them).
- `-value-shape` (multimethod): The shape of one value of the distribution, or
  nil when it is not checked (a product's vector value, or a family that
  declares none).
- `(backend-of & params)`: The backend of the first backend-array parameter
  (else gen.array/\*backend\*).
- `(check ok dist-name message data)`: Throw unless ok, naming the distribution
  and parameter.
- `(check-increasing dist-name param-name v)`: A concrete array parameter must
  increase along its last axis.
- `(check-integer dist-name param-name v min)`: Parameters that count (trials,
  bounds) must be integers, at least min, as check-positive.
- `(check-non-negative dist-name param-name v)`: Parameters must be at least 0,
  as check-positive.
- `(check-not-nan op v)`: Throw if v, a given value, has a NaN element: it
  would make every weight NaN rather than fail. (Read only when concrete.)
- `(check-numeric dist-name param-name v)`: A parameter must be numbers, not
  booleans: gen.array's comparisons take true as 1, so a boolean would pass a
  family's checks as 1.0 (or fail them with a ClassCastException).
- `(check-param-not-nan dist-name param-name v)`: A parameter must not be NaN
  (in any element, read when concrete): a NaN would make every log density NaN
  rather than fail.
- `(check-positive dist-name param-name v)`: Parameters must be positive: host
  values, and the elements of concrete arrays (every particle of a batched
  one).
- `(check-probabilities dist-name param-name ps)`: Concrete probability vectors
  (the last axis) must be non-negative and sum to 1.
- `(check-probability dist-name param-name v)`: Parameters must be
  probabilities in \[0, 1], as check-positive.
- `(check-value-shape d v)`: Throw unless v has the distribution's value shape
  (when it declares one).
- `(defdist dist-name & body)` (macro): Define a distribution: a constructor

### gen.gradients

### gen.inference.diagnostics

Convergence diagnostics for MCMC: effective sample sizes, R-hat and Monte Carlo
standard errors, as Vehtari, Gelman, Simpson, Carpenter and Bürkner (2021),
"Rank-normalization, folding, and localization: an improved R-hat for assessing
convergence of MCMC", define them, and as ArviZ and Stan's posterior package
compute them.

- `(draws traces addr)`: The values at addr of chains of traces, as draws: of
  one chain, a seq of traces (as gen.inference.kernel/run's :traces), a vector
  of numbers; of a seq of chains, a vector of vectors.
- `(ess-bulk draws)`: The bulk effective sample size: the ESS of the
  rank-normalized split chains, how many independent draws the chains are worth
  for the bulk of the distribution.
- `(ess-mean draws)`: The effective sample size of the mean: the ESS of the
  split chains themselves (Stan's basic ESS, ArviZ's "mean" method).
- `(ess-tail draws)`: The tail effective sample size: the smaller of the ESSs
  of the 5% and 95% quantiles, each the ESS of the indicator of draws at or
  below the quantile of all of them.
- `(mcse-mean draws)`: The Monte Carlo standard error of the draws' mean:
  sd/√ess-mean.
- `(mcse-sd draws)`: The Monte Carlo standard error of the draws' standard
  deviation, by the delta method, as ArviZ: for d the draws less their mean,
  √(Var(d²) / (4·E\[d²]·ess)), ess the ESS of d².
- `(r-hat draws)`: The rank-normalized split R-hat: the larger of the split
  R-hats of the rank-normalized draws (the bulk) and of the rank-normalized
  folded draws, their distances from the median (the tails).
- `(split-r-hat draws)`: The split R-hat of the draws themselves, without rank
  normalization: Gelman et al.'s (BDA3), the R-hat of the split chains.
- `(summary draws)`, `(summary draws {:keys [probs]})`: A quantity's summary:
  {:mean :sd :quantiles :mcse-mean :mcse-sd :ess-bulk :ess-tail :r-hat}, over
  all the draws. :sd is the sample standard deviation, and :quantiles a sorted
  map from probability to quantile, at 5%, 50% and 95% or at opts' :probs,
  interpolated linearly between order statistics (the default of numpy and R).

### gen.inference.mcmc

Gradient-based MCMC and optimization over a selection of continuous choices, as
Gen.jl's hmc, mala, map_optimize and elliptical_slice, and Stan's No-U-Turn
Sampler. Each works on any generative function, nested addresses included,
through gen.gradients/choice-gradients.

- `(elliptical-slice trace addr mu cov)`, `(elliptical-slice trace addr mu cov
  key)`: Elliptical slice sampling (Murray, Adams and MacKay 2010) of the
  choice at addr, whose prior is N(mu, cov): a new value on the ellipse through
  the current one and a prior draw, accepted on the slice of the likelihood
  (the update weight less the prior's own ratio, which the ellipse accounts
  for).
- `(hmc trace selection)`, `(hmc trace selection key-or-opts)`, `(hmc trace
  selection opts key)`: Hamiltonian Monte Carlo on the selected choices: L
  leapfrog steps of size eps, with momenta drawn from N(0, M), M the inverse of
  :inv-metric (the identity by default: standard normal momenta).
- `(hmc-particles ps selection)`, `(hmc-particles ps selection key-or-opts)`,
  `(hmc-particles ps selection opts key)`: hmc on every particle of a
  gen.batched collection, n independent chains each accepted on its own: one
  batched gradient per leapfrog step for all of them, where the model runs
  batched.
- `(inv-metric trace selection m)`: The diagonal inverse metric that hmc, mala
  and nuts read from the :inv-metric option m (any form they take, nil the
  identity) for the selection at trace, labeled: a choice map with the selected
  choices' addresses, each holding its variances in the choice's shape (a host
  number for a scalar choice on the JVM backend). gen.inference.nuts returns
  its metrics so.
- `(mala trace selection tau)`, `(mala trace selection tau key-or-opts)`:
  Metropolis-adjusted Langevin: propose v' \~ N(v + tau·∇, √(2 tau)) for the
  selected choices v, with the reverse move's density from the gradient at v'.
- `(mala-particles ps selection tau)`, `(mala-particles ps selection tau
  key-or-opts)`: mala on every particle of a gen.batched collection, as
  hmc-particles: one batched gradient at the start and one at the proposal for
  all of them.
- `(map-optimize trace selection)`, `(map-optimize trace selection opts)`: One
  step of gradient ascent on the log density of the selected choices, with
  backtracking: try the step size max-step-size, shrinking it by tau until the
  score does not decrease (Gen.jl's map_optimize).
- `(map-optimize-particles ps selection)`, `(map-optimize-particles ps
  selection opts)`: map-optimize on every particle of a gen.batched collection,
  each with its own line search: one batched gradient, and one batched score
  per step size tried, for all of them where the model runs batched.
- `(nuts trace selection)`, `(nuts trace selection key-or-opts)`, `(nuts trace
  selection opts key)`: One transition of the No-U-Turn Sampler on the selected
  choices, Stan's (base_nuts.hpp; Betancourt 2017): from momenta drawn as
  hmc's, the trajectory doubles forwards or backwards at random, by leapfrog
  steps of size eps, until it makes a U-turn by the generalized criterion (with
  Stan's extra checks across merged subtrees), a step diverges, or it holds
  2\^max-depth - 1 steps.

  pf_dereplicate!), the groups laid out as replicate makes them (:layout).
  :method :keepfirst (the default) keeps each group's first particle and its
  weight, undoing replicate; :sample draws one in proportion to the group's
  weights and gives it the group's mean weight (:key).
- `(ess state)`: The effective sample size of the particles' weights.
- `(initialize model args observations n)`, `(initialize model args
  observations n opts)`: n particles of model on args, generated with the
  observations (from the internal proposal, or from :proposal).
- `(introduce state observations n)`, `(introduce state observations n opts)`:
  The state with n new particles generated with the observations
  (GenParticleFilters' pf_introduce!), from :model on :args (by default the
  first trace's), by its internal proposal or :proposal on :proposal-args.
- `(log-ml-estimate state)`: The estimate of log p(observations so far):
  unbiased in exp space. (A batched state is spot-checked first:
  gen.batched/check.)
- `(log-weights state)`
- `(maybe-resample state)`, `(maybe-resample state opts)`: Resample when the
  effective sample size is below :ess-threshold (n/2 by default).
- `(mean state f)`: The weighted mean of (f trace) over the particles.
- `(move-reweight state kernel)`, `(move-reweight state kernel key)`: Each
  particle's trace moved by a reweighting kernel (see reweighting), and its log
  weight increased by the move's (GenParticleFilters' pf_move_reweight!;
  Marques and Storvik 2013).
- `(proportions state f)`: The total weight of each value of (f trace)
  (GenParticleFilters' proportionmap): a map of host values to probabilities.
- `(rejuvenate state kernel)`, `(rejuvenate state kernel key)`: Each particle's
  trace moved by kernel, an MCMC kernel ((fn \[trace key] → {:trace …}),
  gen.inference.kernel's, or mcmc's moves) that leaves the posterior invariant,
  so the weights stay as they are (GenParticleFilters' pf_move_accept!).
- `(replicate state k)`, `(replicate state k {:keys [layout]})`: Each particle
  replaced by k copies (GenParticleFilters' pf_replicate!): in contiguous
  blocks (:layout :contiguous, the default; particle 0's copies are 0 … k-1) or
  interleaved (:interleaved; they are 0, n, 2n, …).
- `(resample state)`, `(resample state {:keys [method key priority n]})`:
  Particles drawn in proportion to their weights; the weights become equal, and
  the log marginal likelihood so far moves into :log-ml.
- `(resize state n)`, `(resize state n opts)`: The state with n particles,
  resampled (GenParticleFilters' pf_resize!); options as for resample.
- `(reweighting selection)`, `(reweighting proposal proposal-args)`,
  `(reweighting proposal proposal-args opts)`: A move-reweight kernel
  (GenParticleFilters' move_reweight): (fn \[trace key] → {:trace trace'
  :weight w}), w the move's log importance weight, log p(t')/p(t) - log
  q_fwd(u; t) + log q_bwd(u'; t'): the ratio MH accepts by (mh/move's
  :log-alpha), here a weight.
- `(sample-unweighted-traces state n)`, `(sample-unweighted-traces state n
  key)`: n traces drawn in proportion to the particles' weights.
- `(step state args argdiffs observations)`, `(step state args argdiffs
  observations opts)`: Every particle's trace updated to args with the
  observations (and choices from :proposal), each log weight increased by its
  incremental weight.
- `(traces state)`: The particles' traces (scalar traces, also for a batched
  filter).
- `(update-view state idx f & args)`: state with the particles at the indices
  idx replaced by those of (f view args…), the operation on GenParticleFilters'
  substate: (update-view state idx resample {:key k}) resamples those particles
  alone, (update-view state idx step args argdiffs observations) steps them
  alone. f keeps the number of particles.
- `(variance state f)`: The weighted variance of (f trace) over the particles;
  on a batched state as mean.
- `(view state idx)`: The particles at the indices idx as a state of their own
  (GenParticleFilters' state\[idxs], a ParticleFilterSubState): its traces,
  ess, statistics and samples are those of the subset, and its estimate of the
  log marginal likelihood is the source's so far plus the log mean of the
  view's weights. update-view runs an operation on one.

### gen.inference.proposal

The internal-proposal override (thesis §4.4, Alg. 16, p. 152): a model's
distribution and traces with another internal proposal.

- `(->InternalProposalGF gf q)`: Positional factory function for class
  InternalProposalGF.
- `(choices-of q qargs choices)`: The part of choices that q, run on qargs,
  would propose, found by replaying q against them.
- `(map->InternalProposalGF m)`: Factory function for class InternalProposalGF,
  taking a map of keywords to field values.
- `(regenerate-under generate weight tr args argdiffs selection key)`:
  regenerate for a generative function with an internal proposal (Eq. 4.1): the
  unselected choices of tr are the constraints of both moves, the new trace
  from (generate args sigma key) and the old one weighed by (weight (:args tr)
  sigma tr), both returning the internal proposal's generate weight.
- `(update-under wrapper-name this generate tr args argdiffs constraints key)`:
  update for this, a wrapper of the generative function (:gf this) with an
  internal proposal: gf's update keeps, overwrites and removes choices, a
  change in the arguments' number included, and the fresh choices it makes are
  then drawn by the internal proposal given the kept ones, (generate args kept
  key), weighed against tr's score.
- `(with-internal-proposal gf q)`: gf with q as its internal proposal for the
  choices q makes (see the namespace doc): the same distribution and traces. gf
  and q are dynamic generative functions; q is called as (q constraints &
  args), on gf's arguments, and makes choices at gf's addresses that the
  constraints leave open (one the constraints give is a loud error).

### gen.inference.transform

Gen.jl's trace transform DSL (\@transform) and trace translators (thesis
§3.6–3.7).

- `(->Transform name body inverse)`: Positional factory function for class
  Transform.
- `(copy from-space from-addr to-space to-addr)`: Copy the value or subtree at
  from-addr of an input space to to-addr of an output space, unchanged.
- `(deftransform tname & more)` (macro): (deftransform name doc? \[model-in
  aux-in model-out aux-out] body …).
- `(deterministic-translator opts)`: Gen.jl's DeterministicTraceTranslator: a
  translator whose transform maps the trace's choices to p-new's with no
  auxiliary choices.
- `(extending-translator {:keys [p-new-args p-argdiffs new-observations
  q-forward q-forward-args]})`: Gen.jl's SimpleExtendingTraceTranslator: the
  trace updated to p-new-args (with p-argdiffs, unknown changes by default)
  with :new-observations and the choices of (q-forward trace q-forward-args…),
  mapped by :transform first when given (its model-in is the proposal's
  choices, as GenParticleFilters' ExtendingTraceTranslator, and its model-in
  retval the proposal's return value); the weight is the update's minus the
  proposal's, plus log |det J| (:log-abs-det, 0 without a transform).
- `(inverse t)`: t's inverse, as pair or involutive set it; the inverse's
  inverse is t.
- `(involution t)`, `(involution t {:keys [check? proposal]})`: Transform t as
  the involution of involutive MCMC (Gen.jl's SymmetricTraceTranslator), for
  gen.inference.mh/involutive-mh: (h trace fwd-choices fwd-retval proposal-args
  key) → {:trace :bwd-choices :weight :log-abs-det}, and called directly (h
  trace fwd-choices key), or (h trace fwd-choices) with a key from the implicit
  source, with no forward return value. t's model-out choices update the trace
  with key (every new choice must be written, so the update samples none; the
  key draws a model's encapsulated randomness afresh), its aux-out are the
  backward choices, and the weight is the update's plus log |det J|, which is
  also :log-abs-det: the trace's unwritten continuous reads that update keeps
  count as unchanged outputs.
- `(involutive t)`: Transform t as its own inverse (Gen.jl's is_involution!).
- `(map->Transform m)`: Factory function for class Transform, taking a map of
  keywords to field values.
- `(new-arguments trace p-new-args p-argdiffs)`: \[args argdiffs] for a
  translator's update: p-new-args (the trace's own by default) and p-argdiffs
  (unknown changes by default).
- `(pair f g)`: \[f' g']: transforms f and g, each with the other as its
  inverse, both ways (Gen.jl's pair_bijections!).
- `(read space addr tag)`: The value at addr of an input space (model-in or
  aux-in), tagged :discrete or :continuous.
- `(retval space)`: The return value of the generative function that made an
  input space's choices: model-in's, the trace's (a choice map has none);
  aux-in's, the proposal's that drew the auxiliary choices (involutive MH's
  forward proposal, a translator's q-forward; in a check, the backward one's;
  tf/run's :aux-retval).
- `(run t model-in aux-in)`, `(run t model-in aux-in opts)`: Transform t of
  model choices (or a trace) and auxiliary choices: {:model the model-out
  choices, :aux the aux-out choices, :log-abs-det}.
- `(same-choices? a b)`: Do two choice maps hold the same addresses and (within
  float tolerance) the same values?
- `(tcall t)`: Run transform t's body on the current spaces (Gen.jl's \@tcall).
- `(transform spaces & body)` (macro): A transform: (transform \[model-in
  aux-in model-out aux-out] body …), the four names bound to the spaces read,
  write and copy take (see the namespace doc).
- `(transform? x)`
- `(translator {:keys [p-new p-new-args new-observations q-forward
  q-forward-args q-backward q-backward-args check? prev-observations]})`:
  Gen.jl's GeneralTraceTranslator: (translator trace key) → {:trace :weight
  :log-abs-det}.
- `(unconstrained-additions old-choices constraints discard new-choices)`: The
  addresses of new-choices (an updated trace's) that neither the constraints
  nor the old trace's choices that the update kept (not in discard) account
  for: choices the update sampled.
- `(updating-translator {:keys [p-new-args p-argdiffs new-observations
  q-forward q-forward-args q-backward q-backward-args check?
  prev-observations]})`: GenParticleFilters' UpdatingTraceTranslator.
- `(write space addr value tag)`: Set addr of an output space (model-out or
  aux-out) to value, tagged :discrete or :continuous.

### gen.inference.vi

Black-box variational inference with a generative function as the variational
family (Gen.jl's black_box_vi! and black_box_vimco!).

- `(black-box-vi model model-args observations q q-args store optimizer opts)`:
  Fit q's store by ascending the ELBO (Gen.jl's black_box_vi!).
- `(black-box-vimco model model-args observations q q-args store optimizer
  opts)`: Fit q's store by ascending the K-sample bound with VIMCO's control
  variates (Gen.jl's black_box_vimco!).
- `(elbo-gradient model model-args observations q q-args store n opts)`: One
  iteration's estimates: {:objective the mean log weight (the ELBO), :grads its
  gradient with respect to q's store} from n draws, by the score-function
  estimator, or with :estimator :reparam the pathwise one (see the namespace
  doc for :baseline, :estimator and :batched?); with :model-store, also
  :model-grads, its gradient with respect to the model's store; with :batched?,

  throws with it instead).
- `(vimco-gradient model model-args observations q q-args store k {:keys

  respect to q's store}.

### gen.inference.weights

Log weights of a weighted collection of samples (importance samples,
particles): normalization, effective sample size, the log marginal likelihood
estimate, and resampling.

- `(ess log-weights)`: The effective sample size 1 / Σ p², where p are the
  normalized weights: n for equal weights, 1 when one sample carries all the
  weight.
- `(log-mean-exp log-weights)`: log((1/n) Σ exp(w)): the log marginal
  likelihood estimate of n importance samples with these log weights.
- `(log-sum-exp log-weights)`: log Σ exp(w) of the log weights: -Inf when they
  are all -Inf (a total of 0), and a loud error for NaN or +Inf.
- `(multinomial log-weights n)`, `(multinomial log-weights n key)`: n indices
  drawn independently in proportion to the weights.
- `(normalize log-weights)`: Gen.jl's normalize_weights: {:log-total log Σ
  exp(w), :log-normalized-weights the log weights less log-total, a vector of
  host doubles whose exponentials sum to 1}. :log-weights, wherever a result
  holds it, is the raw log weights.
- `(resample method log-weights n)`, `(resample method log-weights n key)`: n
  indices drawn with method: :multinomial, :systematic, :stratified or
  :residual.
- `(residual log-weights n)`, `(residual log-weights n key)`: whole-copies of
  n·p_i of each sample i (floor(n·p_i), rounded up within a relative 1e-9 of
  the next integer), then the remaining indices drawn multinomially in
  proportion to the residuals n·p_i less those copies.
- `(stratified log-weights n)`, `(stratified log-weights n key)`: n indices at
  the positions (j + u_j)/n, one independent uniform per stratum.
- `(systematic log-weights n)`, `(systematic log-weights n key)`: n indices at
  the evenly spaced positions (j + u)/n, for one uniform u.

### gen.learning

Optimizers for trainable-parameter stores (gen.dynamic/with-params), as pure
functions: Gen.jl's ParamUpdate and apply!, without mutation. Each optimizer
takes a gradient-ascent step on the objective whose gradients are given (e.g.
log densities, from gen.gradients/param-gradients), and returns the new store
with the optimizer's new state.

- `(adam {:keys [lr beta1 beta2 eps]})`: Adam (Kingma and Ba 2015), ascending.
- `(gradient-descent {:keys [step-size-init step-size-beta]})`: Gradient ascent
  with a decaying step: step-size-init · (beta + 1) / (beta + t) at step t
  (Gen.jl's GradientDescent).
- `(init {:keys [kind]} store)`: The optimizer's initial state for store.
- `(lecture model model-args proposal store q-args-fn key)`: The sleep phase of
  wake-sleep (Gen.jl's lecture!): a trace of model on model-args, and the
  proposal, with its parameter store, scored on the choices of that trace it
  makes given (q-args-fn trace). {:score log q of those choices, :grads its
  gradient with respect to the store}.
- `(lecture-batched model model-args proposal store q-args-fn n key)`: lecture
  over n of the model's traces: the mean score and gradient (Gen.jl's
  lecture_batched!).
- `(sgd {:keys [lr]})`: Fixed-step gradient ascent: θ + lr·g (Gen.jl's
  FixedStepGradientDescent).
- `(step optimizer state store grads)`: \[store' state']: one ascent step from
  store along the gradients, evaluated.
- `(train gf store optimizer data-fn gradients-fn {:keys [epochs
  batches-per-epoch batch-size key]})`: Fit the trainable parameters of gf by
  maximizing the log density of generated data (Gen.jl's train!): each of
  :epochs epochs takes :batches-per-epoch steps, each step drawing :batch-size
  examples \[args constraints] from (data-fn key), averaging their
  param-gradients (through gradients-fn, gen.gradients/param-gradients) and
  taking one optimizer step from store.

## The experimental namespaces

### The generative function interface

- `gen.partition`: A batched run's particles in groups: a Switch whose index
  differs across the particles of a batch runs each branch batched over its own
  particles (DESIGN.md §9, docs/array-api.md §8b). Each group runs under a
  part's backend (gen.array.batch/part-backend), which draws for a particle
  what the batch's own run would; the batch's values go in by the group's rows
  (gather-into) and the results come back (scatter). A batched trace holds such
  a call's data by group (gen.array.batch/Parts), each group's data a batch of
  its own particles.

### Distributions

- `gen.dist.commons-math` (in ext/commons-math): Apache Commons Math 3's
  univariate distributions as gen.clj distributions (gen.dist.host), as
  GenDistributions makes Distributions.jl's Gen distributions. Needs the
  :commons-math alias.
- `gen.dist.host`: Distributions backed by a host library, as GenDistributions'
  DistributionsBacked wraps Distributions.jl's: a family of univariate
  distributions given by a host object built from the parameters, its quantile
  function (inverse CDF) and its log density.

### Inference

- `gen.inference.conjugate`: Conjugate proposals: a model's distribution and
  traces, with one latent choice drawn from its exact posterior given its
  observed children (the thesis's optimal internal proposal, §4.1, pp.
  145-146).
- `gen.inference.laplace`: The Laplace approximation and the observed Fisher
  information, from Hessians of a trace's log density: with respect to selected
  continuous choices, or to the trainable parameters its generative function
  holds (gen.gfi/stores).
- `gen.inference.particle-mcmc`: Particle MCMC (Andrieu, Doucet and Holenstein
  2010, "Particle Markov chain Monte Carlo methods", JRSS B): conditional SMC
  and particle Gibbs, over the particle-filter API
  (gen.inference.particle-filter).
- `gen.inference.trace-kernel`: GenTraceKernelDSL's trace kernels: stochastic
  maps between traces that mix sampling with deterministic code, as proposals
  for MH and as the steps of SMCP3.

### Language models

- `gen.llm.branching`: The Branching protocol (DESIGN.md §6): a language
  model's states as branches, the layer under the LM protocol. An engine
  (gen.llm.llama; an MLX-native one later) holds the model; a branch is one
  token sequence the model has read, with the distribution of its next token.
- `gen.llm.bytes`: A vocabulary's bytes: the token byte trie, which grammar
  masks walk (gen.llm.grammar).
- `gen.llm.cache`: The LM protocol's cache over a Branching engine
  (gen.llm.lm): what the engine has read, in a trie of token prefixes
  (gen.llm.trie), and every live branch, each the entry of its context.
- `gen.llm.cells`: The KV cells an LM's branches hold, counted as llama.cpp's
  unified cache counts them, so that gen.llm.cache can keep them under a bound:
  a read of n tokens takes n new cells, a fork shares its branch's cells, and a
  cell is freed when no branch holds it.
- `gen.llm.constrained`: Completions under a potential (gen.llm.token's
  :potential, gen.llm.potential): each token's distribution is the LM's times
  the potential's next-token weights, renormalized at its site. Under a grammar
  (gen.llm.grammar), the LM's row masked to the tokens the grammar allows,
  renormalized: GenMLX's grammar-masked decoder.
- `gen.llm.dfa`: Deterministic finite automata over bytes, the languages of
  grammar-constrained decoding (gen.llm.grammar). gen.llm.regex builds them
  from regular expressions; (dfa spec) from a transition map.
- `gen.llm.grammar`: Grammars: a regular language over bytes (gen.llm.regex,
  gen.llm.dfa) read through an LM's vocabulary, so that token sequences can be
  held to it: masks for grammar-constrained decoding and the weights of a
  potential.
- `gen.llm.host`: The LLM layer's host work off the calling thread: pools of
  daemon platform threads, and an ordered map over one. The llama.cpp engine
  normalizes a decode's rows on one (gen.llm.llama), token SMC draws its
  particles' tokens on another (gen.llm.smc). Each keeps a pool of its own: one
  pool shared by both could deadlock, a task waiting on tasks queued behind it.
- `gen.llm.llama`: The llama.cpp engine (DESIGN.md §6): a Branching engine
  (gen.llm.branching) over one llama.cpp context, through the generated binding
  of llama.h (src-java/gen/llama/ffi, from native/jextract-llama.sh) and the
  libraries of native/build-llama.sh, both pinned to llama.cpp v0.7.0.
- `gen.llm.llama.recurrent`: Where llama.cpp keeps a recurrent or hybrid
  model's states, replayed: the bookkeeping of llama_memory_recurrent
  (src/llama-memory-recurrent.cpp at llama.cpp 620d222, which v0.7.0 builds:
  seq_cp, seq_rm, find_slot), fed every memory operation of the engine, so that
  gen.llm.llama can split a step whose sequences would land far apart. Internal
  to gen.llm.llama. Pinned to that commit: gen.llama.LlamaRuntime refuses any
  libllama but v0.7.0, and a change of version needs this file read against the
  new llama-memory-recurrent.cpp.
- `gen.llm.lm`: The LM protocol (DESIGN.md §6): a language model as a function
  from token contexts to next-token log-probabilities, shaped like
  genlm-backend's AsyncLM. The layer under the token generative function,
  grammar-constrained decoding and token SMC; above the Branching protocol
  (gen.llm.branching).
- `gen.llm.potential`: Potentials: weights of token sequences, after
  genlm-control's Potential, for twisted and grammar-constrained token SMC and
  constrained decoding. A potential weighs a context (a token vector) as a
  prefix and as a complete sequence; the next token's weights follow from
  those.
- `gen.llm.regex`: Regular languages over bytes, as terms, compiled to minimal
  DFAs (gen.llm.dfa) by Brzozowski derivatives: the languages of
  grammar-constrained decoding (gen.llm.grammar).
- `gen.llm.slots`: A Branching engine over numbered sequence slots, as
  llama.cpp's KV cache has them: the lifetimes, capacity and threading of
  gen.llm.branching, written once over the Slots operations an engine
  implements (gen.llm.llama for llama.cpp; a pure-JVM toy engine in the tests).
- `gen.llm.smc`: Token-level sequential Monte Carlo over a completion
  (gen.llm.token), twisted by a potential (gen.llm.potential), as GenMLX's
  token SMC and genlm-control's SMC: particles are token sequences that grow by
  one token a step, reweighted and resampled. The interface is
  gen.inference.particle-filter's.
- `gen.llm.token`: A language model's completions as generative functions
  (DESIGN.md §6, §9), over the LM protocol (gen.llm.lm).
- `gen.llm.trie`: A persistent radix trie of token sequences: the LM protocol's
  record of what its engine has read (gen.llm.cache). Each token on a path
  carries its score, the log-probability it was read with given the tokens
  before it (NaN for a sequence's first token, which has none). A node may hold
  an entry, a value for its context (for the cache, the id of the live branch
  at that context).
