# Third correctness review: the batch tracer and the review fixes (2026-10-19)

An independent read-only review of commits 1fa4ed7..facccad: the batch
tracer and the fixes for the second review. The tracer's ops held up (about
90 per-particle checks, including a 2-d batch shape), as did distribution
log-probs under the tracer, 300-model fuzzing of batched weights, and Switch
weights for dynamic branches. It confirmed 13 bugs, each with a script in
the session scratchpad `review3/`. Fixes are tracked in bean genclj-9559
(see the end of this document).

## Confirmed bugs

- **B1. Host predicates still pick one branch for every particle.**
  `Batched` intercepts `=` only on the left. `(= 0 x)` goes through
  `Long.equals`, and `case` with integer keys, `condp =`, and vector
  `get`/`contains?` miss it too. A mixture model gave batched IS log-ml −18.92
  against −1.596 scalar. `([..] k)` and `(format "%d" k)` crash instead of
  falling back.
- **B2. Regenerate resamples unselected choices** when a Switch has
  non-dynamic branches, or a splice's callee changes to another dynamic GF.
  A Switch of two Maps lost its observations with weight 0; a Switch of two
  distributions resampled an unselected value.
- **B3. Batched runs skip parameter validation** (the batch backend reported
  itself lazy), giving NaN or garbage where scalar runs throw.
- **B4. Batched linalg misaligns per-particle batch axes** when the
  operands' per-particle ranks differ: silently wrong at N = 2, a broadcast
  error at N = 4.
- **B5. A value of the wrong shape is still scored as several draws** for a
  spliced or top-level Distribution (generate, update, assess), for retained
  values whose parameters change shape, and for product factors.
- **B6. Lazy trace calls made while a splice's arguments are realized are
  dropped.** `splice-fn` read the state before the call and `vreset!` it
  after. The compile-time check missed threaded forms such as `->>`.
- **B7. `realize!` forced an infinite lazy return value to a million
  elements** (72 ms and 88 MB per trace).
- **B8. `gen.batched/take` re-runs the whole model**, so a batched particle
  filter with resampling is quadratic in the number of steps (slower than
  scalar past T ≈ 120).
- **B9. Scans and arg-reductions of a per-particle scalar** throw without
  falling back.
- **B10. Unfold with a random length** crashes in batched mode.
- **B11. `gen.batched/traces` fails for a collection of a Distribution**
  (`cm/unstack` of a root value).
- **B12. JVM `solve` does not check the right-hand side's row count.**
- **B13. The default value-shape rejects valid user-defined distributions.**

Plus two needless fallbacks: `(a/full shape batched-value)`, and `a/grad` on
host-only leaves inside a batched body.

## Likely

- **Middleware.** An address-less splice's callee inherits the caller's
  middleware when it has none.
- **Raw values in scalar calls.** A raw batched value passed into a scalar
  call outside the tracer correlates the particles' draws.
- **Fallback detection.** `branch-error?` does not walk `ex-cause`.
- **Nesting.** A nested batched collection of the same size ties inner
  particle i to outer particle i.

## Docstring mismatches

- "Batching never changes meaning" overstated: B1, B3 and B4 contradicted it.
- The linalg comment; `realize!`; "Bodies run to completion" (B6).
- The Switch docstring (B2); `with-dispatch` ("opts as for run");
  `product` (B5); `defdist` (B13).
